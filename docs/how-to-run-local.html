Janitorial Management Dashboard — รันยังไงให้ขึ้น

เป้าหมาย: เข้าใจว่าแต่ละขั้นมีไว้ทำอะไร ไม่ใช่แค่ copy คำสั่ง แล้วแก้เองได้เมื่อไม่ขึ้น

ตรวจแล้วบนเครื่องนี้ · macOS dotnet 10.0.401 node v26.8.2 branch codex/cleaner-scheduling DB = facility_dashboard (ข้อมูลจริงของคุณ)

1 idea หลัก: ต่อ 3 ท่อให้ตรงกัน

โปรเจกต์นี้ไม่ใช่โปรแกรมเดียว แต่เป็น 3 โปรแกรมแยกกัน ที่คุยกันผ่านพอร์ต (port) ถ้าท่อไม่ตรงหรือสตาร์ทผิดลำดับ มันจะไม่ขึ้น

MySQLเก็บข้อมูล:3306
←
API (.NET)สมอง · กติกา · migrate เอง:5001
←
Vite (React)หน้าจอที่คุณเห็น:5173

ลำดับต้องซ้าย → ขวาเสมอ: UI ไม่มีอะไรให้แสดงถ้า API ไม่มีข้อมูล และ API บูตไม่ขึ้นถ้าต่อ DB ไม่ได้

ขั้นตอน (เปิด 2 terminal)

0

เช็คว่า MySQL ตื่นอยู่

brew services list | grep mysql

ต้องเห็น started — ถ้าไม่ ให้ brew services start mysql (API จะ migrate ฐานข้อมูลเองตอนบูต)

1

Terminal 1 — API

cd /Users/macbookair/Projects/Janitorial-Management-Dashboard
dotnet run --project backend/src/JanitorialManagementDashboard.Api \
  --launch-profile http --urls "http://localhost:5001"

ทำไมต้อง --urls: launchSettings.json ตั้ง default ไว้ที่ 5225 แต่ Vite proxy วิ่งไป 5001 — ไม่ใส่ = หน้าเว็บโหลดได้แต่กดอะไรก็ไม่ทำงาน

ทำไมต้อง --launch-profile http: เพื่อให้ ASPNETCORE_ENVIRONMENT=Development (มี Swagger + seed + log ละเอียด)

2

Terminal 2 — หน้าเว็บ

cd /Users/macbookair/Projects/Janitorial-Management-Dashboard
npm --prefix frontend run dev -- --host localhost --port 5173 --strictPort

--strictPort = ถ้า 5173 ไม่ว่าง ให้ฟ้องทันที ไม่แอบย้ายไป 5174 (ซึ่งจะทำให้ URL ที่คุณเปิดค้างไว้ชี้ผิด)

node_modules ติดตั้งแล้วในเครื่องนี้ ไม่ต้อง npm install ซ้ำ

บัญชี login — จุดที่คนพลาดบ่อยสุด

DbInitializer seed ข้อมูลตัวอย่างเฉพาะตอนตาราง users ว่าง ฐานข้อมูลบนเครื่องนี้มีข้อมูลเดิมของคุณอยู่แล้ว จึงไม่ seed ทับ

สถานการณ์ใช้บัญชี
DB ปัจจุบัน facility_dashboardบัญชีที่คุณสร้างเอง (เช่น admin_Tai)
DB ใหม่ที่ยังว่างadmin / admin1234 · แม่บ้าน 1000001 / 0810000001 · หัวหน้า 2000001 / 0820000001

อยากได้ชุดเดโมโดยไม่แตะข้อมูลเดิม — สร้าง DB แยกแล้วรันชี้ไป:

mysql -u root -e "CREATE DATABASE facility_playground CHARACTER SET utf8mb4;"
ConnectionStrings__DefaultConnection="Server=localhost;Port=3306;Database=facility_playground;Uid=root;Pwd=;CharSet=utf8mb4;" \
  dotnet run --project backend/src/JanitorialManagementDashboard.Api \
  --launch-profile http --urls "http://localhost:5001"

กับดัก 4 ข้อ

1. NODE_ENV=production ทำให้เทสพัง ~400 ตัว

shell บนเครื่องนี้ export NODE_ENV=production ไว้ ทำให้ vitest โหลด React production แล้วฟ้อง React.act is not a function ทั้งที่โค้ดไม่ผิด

NODE_ENV=test npm --prefix frontend test
2. อย่า reset facility_dashboard

นี่คือฐานข้อมูลพัฒนาของเจ้าของ (มีข้อมูลทดลองจริง) ใช้ DB ชื่ออื่นสำหรับการทดลองที่ต้องล้างบ่อย

3. GPS อ่านได้เฉพาะ https หรือ localhost

เปิดจากมือถือผ่าน http://<IP> จะขึ้น "อ่านตำแหน่งไม่ได้" ต้องใช้ tunnel (handover §2.9) หรือทดสอบบน Mac แล้วตั้งตำแหน่งใน DevTools › Sensors › Location

4. ฟีเจอร์ "ตารางงาน" ยังปิดอยู่

Scheduling__Enabled=false เป็นค่า default ทำให้ /api/schedules ตอบ 404 และเมนูตารางงานกดแล้วขึ้น error ทั่วไป — ยังไม่ใช่bugที่คุณทำพัง

Scheduling__Enabled=true dotnet run --project backend/src/JanitorialManagementDashboard.Api \
  --launch-profile http --urls "http://localhost:5001"

แบบฝึกหัด 5 นาที (ส่วนที่ทำให้ "เข้าใจ" จริง)

บันทึกการเรียนรู้ (เซฟไว้ ทบทวนรอบหน้า)

  • เข้าใจแล้ว: ลำดับ DB → API → UI และท่อ /api → 5001 คือจุดพังบ่อยสุด
  • ยังไม่แน่: บัญชี login ของ DB นี้ไม่ใช่ชุดเดโมใน README
  • ต่อไป (ถ้าอยาก): ตาม request 1 เส้น ตั้งแต่ /login/admin → proxy → JWT → DB
