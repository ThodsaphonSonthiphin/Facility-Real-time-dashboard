📍 ตำแหน่งปัจจุบัน: Backend ครบถ้วน พร้อมเริ่มพัฒนา Frontend สำหรับ Pilot

เราพัฒนาแกน Backend ของระบบ Pilot ทั้งหมด 4 แผนงานเสร็จสิ้นลงใน Branch feat/attendance-alerts-history (ผ่าน Unit Tests 215 ข้อ และ API Tests 324 ข้อ รวม 539 ข้อทั้งหมด) ฐานข้อมูลมีสคีมารองรับทั้ง Area, Service Points, Round Windows, การลงเวลา 4 จังหวะ, GPS Geofencing, และระบบ Admin สมบูรณ์แบบ

✅ งานที่เพิ่งเสร็จสมบูรณ์ในจุดนี้

  • Admin Attendance Board: ดูอัตรากำลังราย Area และกะ (Present / Working / Break / Done / Covered)
  • Attendance Corrections: Admin แก้ไขหรือเติมเวลาให้แม่บ้านที่ลืมสแกน พร้อมบังคับใส่เหตุผลและบันทึกประวัติ
  • Alerts List & Review: หน้ารวมแจ้งเตือน (สแกนนอกรัศมี GPS, สแกนข้าม Area, ลืมสแกนเลิกงาน) พร้อมฟังก์ชัน "คุยแล้ว ปิดเตือน"
  • Cover Assignment from Alert: มอบหมายทำแทนจาก Blocked Scan ได้ทันทีในคลิกเดียว
  • Audit Log History: หน้าประวัติการทำงานของ Admin แบบอ่านอย่างเดียว กรองตามวันที่, ผู้ทำ และหมวดหมู่ได้

🎯 ก้าวต่อไปที่กำลังจะทำ (Next Immediate Step)

  • อัปเดตหน้า Login (ADR 0054): รองรับแม่บ้าน/หัวหน้า Login ด้วยรหัสพนักงาน + เบอร์โทร
  • หน้าจอมือถือแม่บ้าน (Mobile M1–M3): หน้าสแกนลงเวลาเข้างาน (Check-in), หน้างานของฉัน (My Work) และหน้าส่งงานตามรอบเวลา
  • หน้าจอมือถือหัวหน้า (Mobile M10–M12): หน้าสแกนตรวจงาน (Inspection) และส่งแก้งาน (Rework)
  • หน้าจอ Dashboard ของ Admin (Desktop D1–D9): ปรับหน้าบอร์ดความสะอาดตาม Round Window, แท็บบอร์ดการเข้างาน D2, แท็บรายการเตือน D3 และแท็บประวัติ D9

Phase 0: จุดเริ่มต้น & Walking Skeleton (ก.ย. 2026)

พิสูจน์แนวคิดการสแกน QR บนมือถือแล้วอัปเดต Dashboard ทันที
เสร็จสมบูรณ์ 100%

เริ่มต้นสร้างรากฐานของระบบเพื่อให้มีซอฟต์แวร์ที่ทำงานได้จริง (Working Software) ก่อนเริ่มฝึกงาน 1 ต.ค. 2026 ตาม ADR 0001–0018

Real-time Scan Pipeline ✓

สแกน QR บนมือถือ -> ส่งเข้า MySQL -> ยิง SignalR Hub -> การ์ดบนจอเด้งเปลี่ยนสีทันทีโดยไม่ต้องรีเฟรช

JWT & Refresh Token Architecture ✓

Access Token 5 นาทีในหน่วยความจำ + Refresh Token ใน HttpOnly Cookie หมุนใบใหม่ทุกครั้ง ป้องกัน Token Reuse

Local WiFi Deployment ✓

ทดสอบจริงบนวง WiFi เดียวกันกับ Mac รองรับทั้ง Safari/Chrome บนมือถือ และบันทึก Lessons Learned เรื่อง Reconnect

1

Phase 1: รวบรวม Requirement หน้างานจริง & ออกแบบระบบใหม่ (ต้น ต.ค. 2026)

ปรับกระบวนทัศน์จากระบบห้องทั่วไป สู่ระบบโรงงานอุตสาหกรรมขนาด 6 ตึก 72 Area
เสร็จสมบูรณ์ 100%

นำผลสัมภาษณ์พี่เลี้ยง (6 ต.ค. 2026) มาเขียนเป็นข้อกำหนดสถาปัตยกรรมใหม่ ADR 0026–0057 พร้อมแบบจำลองฐานข้อมูล 15 ตารางและ Wireframe 30 หน้า

Area Assignment (70–72 Areas) ✓

แม่บ้าน 1 คนต่อ 1 Area ประจำทุกวัน มีป้ายลงเวลาเข้างานแยกจากป้ายทำความสะอาด (ADR 0040)

Fixed-time Round Windows ✓

เปลี่ยนจากนับช่วงเวลาลอยๆ เป็นช่วงเวลารอบที่แน่นอน เช่น 07:00–09:00 เลยเวลาขึ้น Overdue ทันที (ADR 0047)

GPS Geofencing (Flag ไม่ Block) ✓

สแกนไกลป้ายระบบรับไว้แต่ติดธงเตือนให้ Admin คุย แต่ถ้าสแกนข้าม Area จะถูก Blocked (ADR 0035, 0041)

4 Attendance Events ✓

ลงเวลา 4 จังหวะ: เข้างาน (Shift-In), ออกพัก (Break-Out), กลับจากพัก (Break-In), เลิกงาน (Shift-Out) (ADR 0050)

2

Phase 2: พัฒนา Backend สำหรับโมเดลข้อมูล Pilot (ต.ค. 2026)

สร้างรากฐาน API, Rules และ Database ครบถ้วนตามมาตรฐาน Clean Architecture
📍 เราอยู่จุดนี้ (Backend สมบูรณ์ 100%)

พัฒนาโค้ดตามแผนงาน 4 แผนงานหลัก (PR #50, #52, feat/pilot-scan-rules, feat/attendance-alerts-history)

Plan 1: Pilot Data Model & DB ✓ เสร็จแล้ว

สร้าง Migration PilotSchema ยุบรวม 14 ตารางหลัก พร้อม User Roles, Signs, Windows และ ScanRecords

Plan 2: Admin Setup Endpoints ✓ เสร็จแล้ว

API จัดการ Area, Service Points, Round Windows, ออก QR Token ใหม่ และบันทึกพิกัดป้ายลง Audit Log

Plan 3: Scan & Attendance Rules ✓ เสร็จแล้ว

คำนวณรอบเวลา (OnTime, Late, OffRound), คำนวณระยะพิกัด GPS Haversine, เช็คสิทธิ์ Area และ Cover Assignment

Plan 4: Attendance Board, Alerts & History ✓ เพิ่งเสร็จล่าสุด

บอร์ดเข้างานราย Area, แก้ไขเวลาพร้อมเหตุผล, หน้ารายการแจ้งเตือน "คุยแล้ว ปิดเตือน", มอบหมายทำแทน, และ Audit Log

3

Phase 3: พัฒนา Frontend ให้สอดคล้องกับ Pilot Data Model (Next Step!)

ปรับปรุง UI ทั้งหมด (มือถือแม่บ้าน, มือถือหัวหน้า, Dashboard ของ Admin)
ก้าวต่อไปที่จะเริ่มทำ

นำ Wireframe 30 หน้าและ Prototype มาเขียนเป็น React Components และ Hooks ตามมาตรฐาน react-structure

Login ด้วยรหัสพนักงาน + เบอร์โทร ○ ถัดไป

ปรับหน้า LoginPage ให้แม่บ้าน/หัวหน้ากรอกรหัสพนักงาน + เบอร์โทร (Admin ยังใช้ Username+Password เหมือนเดิม)

หน้าจอมือถือแม่บ้าน (M1, M2, M3) ○ ถัดไป

หน้าลงเวลาเข้างาน M1 (ดึง GPS อัตโนมัติ), หน้ารวมงานของฉัน M2 (My Work) และหน้าส่งผลทำความสะอาด M3

หน้าจอมือถือหัวหน้างาน (M10–M12) ○ ถัดไป

หน้าตรวจรับงาน (Inspection), ระบุจุดบกพร่อง และสั่งแก้งาน (Rework) เพื่อให้แม่บ้านเห็นบนหน้า My Work

หน้าจอ Dashboard ของ Admin (D1–D9) ○ ถัดไป

แท็บบอร์ดความสะอาด (D1), แท็บบอร์ดการเข้างาน (D2), แท็บแจ้งเตือน (D3), แท็บตั้งค่าจุด (D4/D5) และประวัติ (D9)

4

Phase 4: ทดสอบนำร่องในพื้นที่จริง 1 Area (Pilot Scope)

ทดสอบกับแม่บ้านประจำ Area และหัวหน้างานประจำตึก เพื่อเก็บผลสะท้อนหน้างานจริง
รอเริ่มเมื่อ Frontend เสร็จ

ขอบเขตการนำร่องตาม ADR 0043: ทดสอบที่ Area 1 (AR01) มีป้ายลงเวลา 1 ป้าย และจุดบริการอย่างน้อย 1 จุด

พิมพ์และติดตั้งป้าย QR Sign จริง ○ รอเริ่ม

Admin กรอกข้อมูล Area และจุดบริการในระบบ พิมพ์ป้าย QR ไปติดที่ทางเข้า Area และหน้าจุดบริการ

Admin ยืนบันทึกพิกัดป้าย ○ รอเริ่ม

Admin ถือมือถือไปยืนที่ตำแหน่งป้ายจริง เพื่อกดปุ่ม "บันทึกพิกัดป้าย" ในระบบ (ปรับรัศมีตามสภาพแวดล้อมอาคาร)

ทดลองสแกนจริงในกะเช้า-ดึก ○ รอเริ่ม

แม่บ้านสแกนเข้างาน 4 จังหวะ และส่งงานตามรอบเวลาจริง หัวหน้าเดินตรวจและประเมินผลผ่านระบบ

5

Phase 5: เตรียมความพร้อมสำหรับ Production (Pre-Production)

จัดการด้านความปลอดภัย นโยบายข้อมูล และเครือข่ายระดับองค์กร
วางแผนแล้ว

เตรียมความพร้อมด้านโครงสร้างพื้นฐานและกฎหมายก่อนเปิดใช้งานเต็มทั้งโรงงาน

HTTPS & Cloudflare Tunnel ○ วางแผนแล้ว

เปิดให้มือถือแม่บ้านเข้าถึงระบบผ่านอินเทอร์เน็ต 4G/5G ด้วย HTTPS และเปิดใช้งาน Secure Cookie (ADR 0049)

นโยบาย PDPA & HR ○ วางแผนแล้ว

ประสานงานฝ่าย HR เรื่องการขอความยินยอมเก็บพิกัด GPS เฉพาะช่วงเวลาปฏิบัติงาน (ADR 0055)

Excel Account Import ○ วางแผนแล้ว

นำเข้ารายชื่อแม่บ้าน ~170 คน และหัวหน้างาน จากไฟล์ Excel ก่อนเริ่มเปิดระบบ (ADR 0056)

Phase 6: ขยายผลใช้งานเต็มรูปแบบทั่วทั้งโรงงาน (Full Scale Rollout)

จุดปลายทางสุดท้าย: ครอบคลุม 6 อาคาร, 70–72 Areas, แม่บ้าน 170 คน

ติดตั้งป้ายครบทุกอาคาร 🏁 จุดหมาย
