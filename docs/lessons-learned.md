# บันทึกบทเรียนจากการทดสอบใช้งานจริง (Lessons Learned)
## Facility Real-time Dashboard POC

เอกสารบันทึกบทเรียนและข้อค้นพบจากการทดลองนำระบบไปใช้งานและสแกนจริงด้วยโทรศัพท์มือถือผ่านเครือข่าย WiFi วงเดียวกับโฮสต์ (Mac) ตามที่ระบุไว้ใน [ADR 0009: Delivery Plan — 3-Phase Walking Skeleton](file:///Users/macbookair/Desktop/Facility-Real-time-dashboard/docs/adr/facility-0009-delivery-plan-walking-skeleton.md) เพื่อใช้เป็นฐานข้อมูลและแนวปฏิบัติก่อนเข้าสู่การฝึกงานจริงในวันที่ 1 ต.ค. 2026

### 1. ความเสถียรของ WiFi และการ Reconnect ของ SignalR

| มิติที่สังเกต | พฤติกรรมที่พบจริงในการทดสอบ | การรับมือและแนวปฏิบัติสำหรับ Production |
|---|---|---|
| **การพักหน้าจอ / สลับแอปบนมือถือ** | เมื่อมือถือปิดหน้าจอ (Sleep Mode) หรือสลับไปเปิดแอปอื่น ระบบปฏิบัติการ (iOS/Android) จะระงับ (Suspend) การทำงานของ WebSockets/SignalR Connection ทันที | คอนฟิก `@microsoft/signalr` ให้มีระบบ **Auto-Reconnect** (`withAutomaticReconnect([0, 2000, 5000, 10000, 30000])`) พร้อมสถานะไฟแสดงบนหน้าจอ Dashboard (เขียว = Live, ส้ม = Reconnecting, แดง = Offline) |
| **การตกหล่นของข้อมูลระหว่าง Reconnect** | ในช่วงที่อุปกรณ์หลุดจากเครือข่ายและเชื่อมต่อกลับมาใหม่ อาจมีอีเวนต์ `ScanRecorded` เกิดขึ้นระหว่างนั้น ทำให้ข้อมูลบน Dashboard ไม่ตรงกับฐานข้อมูล | เมื่องาน Reconnect สำเร็จ ต้องยิงดึง **Snapshot ล่าสุด** (`GET /api/service-points`) ทันที 1 รอบ เพื่อชดเชยข้อมูลที่ขาดหายไประหว่างออฟไลน์ พร้อมตั้งรอบสำรอง Polling ทุก 30 วินาที |
| **Serialization Delay ของ SignalR** | ค่าสถานะ (Enum) เริ่มต้นส่งเป็นตัวเลข (Integer) ทำให้ Frontend จับคู่สตริง (`Normal`, `Issue`) ไม่ได้ ต้องรอรอบ Fallback Polling 30 วินาที | บังคับใช้ `JsonStringEnumConverter` บน SignalR และเพิ่ม Map Helper ฝั่ง Frontend เพื่อให้อัปเดตสถานะแบบเรียลไทม์ภายใน < 0.1 วินาที |

### 2. ระยะเวลาเฉลี่ยและปฏิสัมพันธ์ในการสแกนแต่ละจุด (Scan Ergonomics)

| ขั้นตอน / รูปแบบการสแกน | ระยะเวลาเฉลี่ย | ข้อค้นพบและจุดที่ปรับปรุง |
|---|---|---|
| **การเปิดหน้าสแกนครั้งแรก (Authentication)** | ~10–15 วินาที | ต้องล็อกอินบัญชีแม่บ้าน (เช่น `somchai`) ก่อนครั้งแรก จากนั้นระบบจำ Persistent Session ผ่าน HttpOnly Refresh Token ทำให้อยู่ได้นาน 30 วันโดยไม่ต้องพิมพ์รหัสผ่านซ้ำอีก |
| **การสแกนรอบปกติ (1-Tap Normal Submission)** | **~3–5 วินาที** | แม่บ้านเปิดกล้องมือถือ/LINE ส่องป้าย QR Sign -> กดเปิดลิงก์ -> แตะปุ่ม "เรียบร้อย (Normal)" 1 ครั้ง ข้อมูลบันทึกและส่ง SignalR ขึ้นจอ Dashboard ทันที ถือว่าเร็วมากสำหรับงานหน้างาน |
| **การบันทึกรายงานปัญหา (Issue Reporting)** | **~10–20 วินาที** | แตะเปลี่ยนสถานะเป็น "พบปัญหา" -> ติ๊กเลือกแท็ก (เช่น น้ำยาหมด, พื้นเปียก, ถังขยะเต็ม) -> พิมพ์หมายเหตุสั้นๆ (ถ้ามี) -> กดยืนยัน |
| **การแก้ปัญหาและสะสมประวัติ (Cumulative Issues)** | ~5 วินาที | กรณีจุดบริการมีปัญหาค้างอยู่ ระบบดึงแท็กปัญหาเดิมมาแสดงเพื่อสะสมร่วมกับรายการใหม่ได้ ไม่ถูกเขียนทับ และมีปุ่ม **1-Tap Resolution** สำหรับเคลียร์ปัญหาทั้งหมดกลับเป็นปกติทันทีที่ทำความสะอาดเสร็จ |

### 3. ข้อจำกัดของเบราว์เซอร์บนมือถือรุ่นต่างๆ (Mobile Browser Quirks & Gotchas)

1. **In-App Browser (กล้อง LINE / สแกนเนอร์ในแอปอื่น):**
   - การเปิดลิงก์ผ่าน In-app browser ในบางแอป มีข้อจำกัดเรื่องการแยกคุกกี้เซสชันออกจากเบราว์เซอร์หลัก (Safari/Chrome)
   - แนะนำให้ผู้ใช้งานเปิดด้วยเบราว์เซอร์มาตรฐานของเครื่อง (Safari บน iOS, Chrome บน Android) หรือกด "Open in External Browser" เพื่อให้ Persistent Session ทำงานได้เต็มประสิทธิภาพ

2. **HTTP vs HTTPS ในเครือข่าย Local WiFi:**
   - การทดสอบในวง WiFi ใช้วิธีเรียกผ่าน IP ตรง (`http://<LAN_IP>:5173`)
   - ทำให้คุกกี้ Refresh Token ไม่สามารถเปิดแฟล็ก `Secure: true` ได้ (จำเป็นต้องใช้ `SameSite=Lax; Secure=false` ชั่วคราวเฉพาะตอนทดสอบ)
   - **บทเรียนสู่งานจริง**: ในสภาพแวดล้อม Production ต้องรันผ่าน HTTPS เพื่อให้ใช้ `Secure: true` และเปิดใช้งานฟีเจอร์กล้อง PWA เต็มรูปแบบ

3. **CSS Stacking Context และขนาดหน้าจอเล็ก:**
   - การใช้ `backdrop-filter` ใน CSS Grid ของการ์ด ทำให้เกิด Stacking Context ซ้อนทับ ส่งผลให้ QR Modal ถูกการ์ดแถวล่างบัง
   - แก้ไขโดยใช้ React Portal (`createPortal(..., document.body)`) เรนเดอร์ลอยเหนือระดับ DOM ปกติ
   - หน้าจอขนาดเล็กต่ำกว่า 360px การ์ด Grid แบบเดิมจะล้นขอบ ปรับโครงสร้างเป็น `1fr` พร้อม `justify-content: center` เพื่อรองรับจอมือถือทุกขนาด

4. **React Asynchronous State Closure:**
   - การกดเปลี่ยนสถานะแล้วส่งข้อมูลทันที หากอ่านค่าจาก React State ใน Closure จะได้ค่าเก่า
   - แก้ไขโดยส่งค่า Parameter สถานะที่แน่นอนผ่านฟังก์ชันบันทึก (`submitScan(overrideStatus)`) โดยตรง

### 4. สรุปความพร้อมก่อนฝึกงาน 1 ต.ค. 2026

- **Core Walking Skeleton**: ทำงานได้ครบ 100% (สแกนจริงบนมือถือ -> ส่งเข้า MySQL -> แจ้งเตือนขึ้น Dashboard แบบเรียลไทม์)
- **ระบบความปลอดภัย**: มีระบบ Authentication รองรับทั้ง Cleaner และ Admin ผ่าน JWT + หมุน Refresh Token
- **การจัดการจุดและป้าย QR**: Admin สามารถเพิ่มจุดบริการและออกป้าย QR Sign ใหม่สำหรับสั่งพิมพ์ได้เอง
