# Janitorial Management Dashboard UX/UI audit

## Decision

The owner approved and implementation is complete for **UX-01**, **UX-02** and **UX-03**. The fixes add check-in read recovery, simplify the Admin and Supervisor mobile shell, and make overflowing tables discoverable by touch and keyboard. **UX-04** and **UX-05** remain optional and were not implemented. No finding warranted a Critical rating or a product-wide redesign.

## Phase 1 · Coverage and method

The Thai interface uses React 19, React Router 7, Vite, Redux Toolkit / RTK Query, Tailwind 4 and Lucide. The router separates role access and preserves QR destinations through login. Admin screens load on demand. The API owns attendance, scheduling and authorization decisions. The UI displays their outcomes. Shared components supply page states, fields, buttons, focus rings, overlays, status labels, tables and responsive shells. The existing design system specifies device typography, text with status colors, and action sizes for desk and phone use. ### Nielsen's 10 heuristics

| Heuristic | What the audit found |
|---|---|
| H1 · Visibility of system status | Dashboard showed its loading and empty states. Check-in announced a successful synthetic save. Existing live labels distinguish stale data. F01 covers recovery when opening check-in fails. |
| H2 · Match the real world | Phone screens use Thai terms for work, shift, area and scan actions. The attendance timeline follows the shift in order. Keep these labels and the sign-based workflow. |
| H3 · User control and freedom | Phone routes provide return links. Native dialogs handle Escape and restore the opening control. A failed check-in load leaves the user with back or browser reload. F01. |
| H4 · Consistency and standards | Pages reuse shared controls and state treatments. Table scroll behavior is implicit across the shared table and the separate schedule table. Phone and Admin login associate errors differently. F03 and F04. |
| H5 · Error prevention | Destructive confirmations and pending-state guards are already in place. Check-in hides actions while required reads are stale or failed. Preserve that guard when adding retry. F01. |
| H6 · Recognition rather than recall | Named status chips, clear filter labels and schedule dates support scanning. Off-screen days and actions are poorly signposted on narrow tables. F03. |
| H7 · Flexibility and efficiency | Admin navigation has eleven links ahead of page controls, with no bypass. Narrow tables need a discoverable keyboard and touch entry point. F02 and F03. |
| H8 · Aesthetic and minimalist design | On desktop the dashboard heading starts at y=24. On mobile the repeated navigation moves the same heading to y=548. The Supervisor roster spends a separate banner on branding/account controls before its own heading. F02. |
| H9 · Recognize, diagnose and recover from errors | Existing GPS help gives contextual recovery. Several read errors display “try again” without a relevant control. Phone login attributes a combined credentials failure to one field. F01, F04 and F05. |
| H10 · Help and documentation | Current inline help explains QR use, attendance timing, dashboard cards, and audit history. Add narrow-table guidance where it is needed. F03. |

## Phase 2 · Prioritized findings

“Browser” identifies behavior reproduced with a fixture. “Source” identifies code evidence awaiting a rendered check.

Both reads gate attendance actions. Keep retry on the two reads and preserve all mutation guards. |
| **F02** | **Medium · Browser + source · H7/H8.** Admin Dashboard, Attendance and Schedule headings started at y=548 at 375 px and y=24 at 1280 px. Tab reached eleven menu links and logout before page controls on Admin Schedule. The Supervisor roster heading started at y=283 on phone and carries the wide shell account pane on desktop. | **F03** | **Medium · Browser + source · H4/H6/H7/H10.** At 375 px the schedule was 720 px in a 325 px scrollport, and attendance was 900 px in a 325 px scrollport. The document stayed at 375 px. | **F04** | **Medium · Browser + source · H4/H9.** Employee login shows a combined ID/phone error and marks the phone invalid. The phone stays described by its static hint. | **F05** | **Low · Source · H4/H9.** History has a retry for the actor list but none for the log query. Buildings, area detail/form and sign capture use error notes without a read retry. [History](../../../frontend/src/pages/history/HistoryPage.tsx#L28) · [Buildings](../../../frontend/src/pages/buildings/BuildingsPage.tsx) · [Areas](../../../frontend/src/pages/areas/AreasPage.tsx) · [Area form](../../../frontend/src/pages/areas/AreaFormPage.tsx) · [Sign capture](../../../frontend/src/pages/capture/CapturePage.tsx#L74) | After a temporary error, a setup or reporting user has to reload or repeat a selection. ## Implementation progress

- **UX-01 · Complete.** Check-in load errors offer a full-width retry that refetches both existing read queries. It displays a loading label and disables itself while either read is fetching. Check-in and transfer submissions remain hidden until both reads succeed. The CheckInPage test passed 36/36, covering failed work and sign reads, recovery, and pending state. [Check-in page](../../../frontend/src/pages/check-in/CheckInPage/CheckInPage.tsx) · [Check-in tests](../../../frontend/src/pages/check-in/CheckInPage.test.tsx)
- **UX-02 · Complete.** Admin navigation is a mobile button disclosure with `aria-expanded`, Escape-to-close and focus return, and close-on-navigation. A skip link targets the content. The desktop menu remains in the sidebar. The Supervisor roster uses a compact return/account header. Dashboard, AdminNav and SchedulePage tests passed 36/36. Chromium inspected both pages at 375 and 1280 px. The mobile Admin heading moved from y=548 to y=121 and the Supervisor heading from y=283 to y=80. The desktop Admin menu remains visible. Keyboard checks confirmed the skip link target and menu Escape behavior. No document-width overflow appeared. [Layout and menu code](../../../frontend/src/shared/components/AppLayout.tsx)
- **UX-03 · Complete.** Shared tables and the weekly roster expose a named, focusable region only when the table exceeds the viewport. Small screens show scrolling guidance. The roster keeps the Cleaner name column visible while moving across dates. Arrow Left/Right and Home/End move the focused scroll region while leaving nested links and buttons in control of their own keys. Nine focused test files passed 117/117. Chromium at 375 px measured the weekly roster at 720 px in a 341 px scrollport and verified keyboard movement. At 1280 px the 1166 px table fits its scrollport and adds no tab stop. The attendance table also passed the narrow scroll check. Chromium computed the sticky row header as `position: sticky`. [Shared scroll component and tests](../../../frontend/src/shared/components/Boxes.tsx) · [Weekly roster](../../../frontend/src/pages/schedules/SchedulePage/SchedulePage.tsx)

Final checks passed with `npm --prefix frontend run lint` and `npm --prefix frontend run build`. The build output includes a 132.82 kB gzip main JavaScript bundle and a 9.08 kB gzip stylesheet. The browser fixture did not exercise production API responses, live hub behavior or actual phone hardware. UX-04 and UX-05 were not changed.
